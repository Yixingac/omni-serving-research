# 负载定义

配置文件在 `configs/workloads/`。所有负载都用流式输出（SSE）、`temperature=0`，并且记录输出长度。同一次对比使用相同的负载文件和随机种子。

| 编号 | 文件 | 输入 → 输出 | 内容 | 作用 |
|---|---|---|---|---|
| W1 | `w1_text_chat.json` | 文本 → 文本 | 约 200 token 的合成笔记，要求两句话总结；`max_tokens=128` | 纯语言模型路径的基线 |
| W2 | `w2_audio_text.json` | 语音 + 文本 → 文本 | 合成语音提问（约 3–8 秒），回答一个数字；答案可核对 | 音频编码器 + thinker |
| W2L | `w2l_long_audio_text.json` | 长语音 + 文本 → 文本 | 合成朗读段落（约 10–40 秒），一句话总结 | 长音频的编码与预处理开销 |
| W3 | `w3_audio_speech.json` | 语音 + 文本 → 文本 + 语音 | 同 W2 的提问，用一句话语音回答 | 完整的语音到语音路径 |
| W3b | `w3b_text_speech.json` | 文本 → 文本 + 语音 | 6 个固定的短问题，两句话语音回答 | 去掉音频编码，单独看 talker 和 code2wav |
| W4 | `w4_video_text.json` | 视频 + 文本 → 文本 | 合成视频（移动的彩色圆，8 fps，640×360，2/5/10/20 秒），回答圆的个数 | 视频解码、抽帧和视觉编码的开销 |
| W5 | （所有负载的流式部分） | — | 记录首个文本块、首个音频块的时间和音频块到达间隔 | 流式延迟和播放卡顿 |
| W6 | 实验中的 `agent` 阶段 | 多种 | 带工具调用的 Agent 会话，见下文 | 真实 Agent 负载 |

全双工交互（`/v1/realtime`）不在第一批实验里，原因见 `docs/01_research/research_questions.md`。

## W6：Agent 会话

代码：`src/omni_research/tracing/agent_harness.py`。

- **任务**：三类，按种子生成，答案可以自动判分：
  - 算术应用题（例如“一箱 47 盒，每盒 86 个零件，取走 12 个，还剩多少”）；
  - 单位换算（英里/公里、千克/磅、英寸/厘米）；
  - 库存汇总（查询两个仓库的某种物品数量后相加）。库存数据是虚构的，由种子生成。
- **工具**：`calculator`（只允许算术表达式，用 AST 安全求值）、`convert`、`inventory`，都在本地确定性执行。可以给每次工具调用加上模拟的远程延迟（对数正态分布，例如中位数 0.3 秒），trace 里标为 `synthetic_latency`。
- **协议**：Agent 要求模型每次只回复一个 JSON：`{"tool": ..., "args": ...}` 或 `{"final": ...}`。这样不依赖服务端是否实现了 tool calling 接口。
- **语音版本**：问题用合成语音输入（`input_modality: audio`），最后一步把答案用语音说出来（`speak_final: true`），可以加合成的用户思考时间。
- **记录内容**：因为任务都是合成的，trace 用 `content_policy=public`，保存每个模型请求的完整请求体，回放时可以原样重发。

## 并发与到达方式

- **闭环（closed loop）**：N 个客户端，每个收到回答后立刻发下一个请求。用于找吞吐上限和延迟随并发的变化（并发 1, 2, 4, 8, 16, 32, 64，按实验而定）。
- **开环（open loop）**：按 Poisson 过程以固定速率发请求，不管前一个是否完成。用于固定“提供的负载”。
- **Agent 回放**：见 `docs/04_experiments/benchmark_methodology.md` 的两种回放模式。

每个并发级别先发 warmup 请求（默认与并发数相同），warmup 不计入统计。并发扫描在错误率超过 20% 或延迟中位数超过阈值时停止升级，并记录停止原因。
