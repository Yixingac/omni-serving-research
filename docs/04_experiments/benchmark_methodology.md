# 测量方法

## 基本规则

1. **配置固定并记录**：每个实验目录的 `manifest.json` 记录主机、实际可见的 GPU、本仓库的 git commit（是否有未提交修改）、sglang-omni 的 commit、Python 包版本、模型 revision；`config.json` 是实际运行的配置。
2. **profiler 关闭时测基线**：延迟和吞吐的基线不开 Nsight 和 torch profiler。服务端请求事件记录器开销较低，但也只在单独的“带事件”阶段开启，并且用同样的负载各跑一遍有事件和无事件的版本（x8），评估记录本身的开销。
3. **warmup 和重复**：每个并发级别先发 warmup 请求；需要比较两种配置时，至少重复两次或交替运行，减少运行顺序带来的偏差。
4. **失败不丢弃**：失败的请求计入错误数，失败的实验保留目录和日志，在报告里列出。
5. **输出要验证**：smoke 阶段检查文本非空、要求语音时确实有音频；能核对答案的负载（W2、W4、Agent 任务）记录正确率。
6. **结论分级**：报告中的每条结论标为实际测量、计算结果、估算、假设或未知。

## 闭环与开环

- **闭环并发扫描**：N 个客户端各自串行发请求。它回答“并发为 N 时延迟和吞吐是多少”，但到达速率会随服务变慢而自动降低，所以看不到排队崩溃。
- **开环**：按 Poisson 过程以速率 λ 发送，不等前一个完成。它回答“提供 λ 的负载时系统是否跟得上”。延迟随 λ 急剧上升的位置就是饱和拐点（saturation knee）。

## 两种 trace 回放

代码：`src/omni_research/replay/engine.py`。

- **模式 A，请求级（开环）回放**：每个模型请求在 trace 记录的到达时间（除以 `speed`）发出，不管它依赖的请求是否已经完成。它把“提供的负载”固定为原始 trace 的样子，适合在多个配置之间做公平对比。代价是：服务变慢时，回放里会出现原始 Agent 不可能发出的请求（因为真实的 Agent 要等上一个回答）。
- **模式 B，依赖感知（闭环）回放**：一个请求要等它依赖的请求和工具调用结束后才发出，再加上原始 trace 里记录的客户端间隔（Agent 处理、工具时间、用户思考时间，除以 `speed`）。服务端的延迟会反过来影响后续请求何时发出，和真实 Agent 一样。

两种模式都支持复制会话（`session_copies`）和重新安排会话的开始时间（按原 trace、同时开始、等间隔、Poisson），用来把负载放大到高于原始 trace 的并发。回放产生的每个请求都记录原始 span id，可以逐个对照。

回放请求的内容：如果 trace 保存了请求体（`content_policy=public`，我们的合成任务都是这样），就原样重发；否则按记录的大小构造替代输入（文本长度、音频时长），这时模型的输出长度会和原来不同，结果里标为 `surrogate`。

相关工作的情况：上游基准只有固定集合的闭环和合成的 Poisson 到达；在审阅的来源中，没有找到在真实硬件上比较“按时间戳开环回放”和“依赖感知回放”的工作（`docs/01_research/prior_work.md`）。x6 实验直接比较这两种模式。

## 多 GPU 实验

- **扩展性对比**和**相同预算下的放置对比**分开报告。增加 GPU 带来的提升，不能归功于某种放置或调度。
- 第一批（Job 409712，3 张卡）只能做 1 卡和 2 卡预算：
  - 1 卡：所有阶段在一张卡上（x3、x3r）；
  - 2 卡：两个完整副本加客户端路由（x7a）、thinker 和 talker 拆到两张卡（x7b）、thinker 一份但 talker+code2wav 复制两份（x7c）。每种都跑同样的语音输出并发扫描，以及 Agent trace 的依赖感知回放。
- 3 卡：Qwen3-Omni 的 thinker TP=2 + talker（x9），这是放下 BF16 模型的最低配置。
- 上游已经在 H200 上用固定 TTS 负载做过类似的放置对比（#1235、#1175）。我们的对比是在 PCIe/部分 NVLink 的 A6000 上复核，并加上 Agent 负载，结果会和上游的条件一起说明。

## 实验之间的干扰

同一个作业里，几个单卡实验可能同时在同一节点上运行。它们有各自的 GPU 和 CPU 核，但共享 PCIe、内存带宽、页缓存和 NFS。编排器的 `events.jsonl` 记录每个实验的开始和结束，报告会列出每个实验运行时同时在跑的其他实验。需要严格隔离的对比（例如 x4 与 x4c）会在报告里注明当时的并行情况；如果发现干扰，会单独重跑。

## 停止条件

- 并发扫描在错误率超过 20%，或延迟中位数超过阈值（文本 60 s、语音 90–120 s）时停止升级，并记录原因。
- 每个实验有超时（`timeout_s`），超时会被终止并记为 `timeout` 失败。
- 作业剩余时间不足 15 分钟时不再启动新实验，正在运行的实验收到 SIGTERM 后保存已有数据再退出。
