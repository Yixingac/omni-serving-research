# 实验 6–8 的发现

> 2026-11-17。MiniCPM-o 4.5，sglang-omni 520b49ee（加测量补丁），一台 8×A6000 节点（compute-03，Slurm Job 454290）。
> 每条结论标明性质：**实测**（直接测到的数）、**推算**（由实测数计算得出）、**估算**（带假设的预测）、**假设**（还没有验证的解释）、**未知**。
> 实验 7 的数据和实验 8 第三阶段的性能对比还在运行，对应部分标为“待补”。

## 一、真正的瓶颈在哪里

在 2+6 分工（GPU 0、1 跑 thinker；GPU 2–7 每张卡跑一个 talker 和一个 code2wav）、W3b 负载（文字提问、文字 + 语音回答）下：

1. **高负载时，吞吐被 code2wav 卡住**（实测 + 推算，实验 6）。
   - code2wav 每个请求要固定花约 0.2 秒 GPU 计算：flow 约 150 毫秒，HiFT 约 45 毫秒（实测，B 段 CUDA event）。
   - 一批里请求再多，每个请求分摊的时间也不变（实测，图 5），所以 6 个副本最多约 27–30 请求/秒（推算），还要和同卡的 talker 分时间。
   - 并发 256 时实测吞吐 22.7 请求/秒，talker 卡 91% 的时间在忙（实测）。
2. **每个请求在 code2wav 里的时间，从并发 8 的 0.15 秒涨到并发 256 的 5.2 秒**（实测，均值）：42% 在收件队列里排队，58% 在等自己这一批（平均 8 个、最多 16 个请求）一起算完。
3. **thinker 每一步的 GPU 空档是可以去掉的浪费，但它不是高负载时决定吞吐的瓶颈**（实测，实验 8 第一阶段）。
   - 同步执行时，thinker 每步算 24–26 毫秒、空 3–15 毫秒；
   - 提前一步发射可以把空档降到 ≤ 0.2 毫秒。

## 二、为什么

- **code2wav 的计算量随“请求数 × 帧数”增长，凑批省不下来**（推断，依据实测的“每个请求分摊时间不随批变小”）。
  - flow 要补齐到这一批最长的请求；HiFT 按长度分组，各算各的。
  - 并发 256 时，大批每帧反而比单个请求贵约 20%（实测：160 对 132 微秒/帧），可能是补齐的浪费（假设）。
- **高负载时 code2wav 是 GPU 算不过来，不是 CPU 发命令慢**（实测，实验 6 的 kernel trace）。
  - kernel 发出后要在队列里等 12–94 毫秒才开始跑；
  - GPU 上 flow 的跨度比 CPU 发完它的时间长约 30%；
  - 低负载时正好相反，kernel 发出后 0.08 毫秒就开始跑，GPU 在等 CPU。
- **和 talker 同卡会互相拖慢**（实测，相关）：同样是批大小 1、走 CUDA graph 的 flow，每帧 GPU 时间从并发 8 的 104 微秒涨到并发 64 的 169 微秒（+62%）。因果关系由实验 7 检验（待补）。
- **thinker 的语音请求不能提前发射**（实测阅读源码 + 实测）。
  - 提前发射时，下一步的 CUDA graph 重放会覆盖上一步的隐藏状态，而 MiniCPM-o 是在“收尾”时才去读它（`omni_scheduler.py` 第 3631 行起先发射、再收尾；上游 `lookahead_eligible` 的文档字符串写明了这一点）。
  - 我们的压测客户端还给每个请求带了 `seed: 0`，这会让纯文字请求也走不了提前发射（实测：去掉种子前 0%，去掉后 100%）。

## 五、已证实和推测

**已证实（实测）**：
- code2wav 各段时间的拆分、凑批不省时间、高负载时 kernel 在 GPU 上排队；
- 提前发射去掉了纯文字的 thinker 空档；
- 语音提前发射时隐藏状态确实会被覆盖；
- 快照原型的输出逐位正确。

**推算**：
- code2wav 每个副本约 5 请求/秒的处理能力；
- 补录 CUDA graph 每帧省 4–16%（假设时间和帧数成正比）。

**假设，还没有验证**：
- HiFT 开头的同步来自 Python 列表索引引起的同步拷贝；
- 大批每帧更贵是因为补齐到最长请求；
- 纯文字提前发射后 TTFT 变长，是因为新请求到达时要先收尾在途的那一步；
- 原版同一个问题重复几次结果不同，是因为前缀缓存命中改变了 prefill 的计算。

**未知**：
- 开 profiler 时 code2wav 进程段错误（30 段里 4 次）的确切原因；
- nsys 和 ncu 能否在这个 CUDA 13 环境下使用（没有测试）。
